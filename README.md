# Jelly Fruit

Мобильный прототип гиперказуальной React-игры: квадратные фрукты с упругой деформацией падают в стеклянный контейнер. Два одинаковых кубика сливаются в следующий фрукт; цель — арбуз **2048**.

## Запуск

```sh
npm ci
npm run dev
```

```sh
npm test          # проверки физики и правил
npm run build    # TypeScript + production-сборка в dist/
npm run preview
```

Браузерные проверки выполняются отдельно при запущенном сервере:

```sh
npx playwright install chromium
npm run test:browser
# Для уже установленного Chromium:
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
# Для проверки production-сборки или вложенного пути Pages:
GAME_URL=http://localhost:4173/2048Game/ npm run test:browser
```

## Управление

- Игра начинается с пустого контейнера; числовых бейджей на фруктах нет.
- Веди пальцем и отпускай для броска. На компьютере — мышь и клик.
- Стрелки ← / → прицеливаются, пробел / Enter бросает, когда игровое поле в фокусе.
- Три встряски на игру бесплатны; дополнительная стоит 25 монет. Каждое слияние приносит от 1 до 10 монет в зависимости от ступени нового фрукта.
- Кубики выше пунктирной линии заканчивают игру после 1,2 секунды переполнения, даже если стопка продолжает двигаться. Новый или слившийся кубик получает 1,3 секунды на падение; красная полоса показывает отсчёт.
- Рекорд, монеты, открытые фрукты и настройки звука и вибрации, покупки и выбранное оформление сохраняются локально. Крупная лента фруктов прокручивается пальцем и стрелками; неоткрытые фрукты показаны чёрными силуэтами. Есть настройки звука и вибрации, полный экран, справка, баланс монет и подтверждение перезапуска. Открытые окна приостанавливают физику.
- Лента имеет инерцию, сопротивление на краях и пружинный возврат. На компьютере также доступны перетаскивание мышью, колесо, стрелки и Home / End при фокусе на ленте. Её края плавно затухают.

## Физика и производительность

Фрукт — физическое мягкое тело: восемь точек по контуру и одна в центре, 20 упругих связей и ограничение площади. Verlet-интеграция и XPBD-связи сохраняют объём, дают граням прогибаться при ударе и постепенно возвращают квадратную форму. Контакты рассчитываются по текущему деформированному контуру, давление распределяется на его ближайшие точки. Ограничитель формы предотвращает складывание и чрезмерное растяжение при переполнении.

Физика работает с фиксированным шагом 60 Гц и шестью итерациями решения. Пространственная сетка отбирает только соседние пары. Успокоившиеся тела засыпают. Спрайт следует тем же восьми точкам через восемь текстурированных треугольников. Для каждого фрукта измерены границы видимой мякоти: прозрачные поля не уменьшают текстуру относительно коллайдера, листья продолжаются за его пределами. Деформированный спящий фрукт кэшируется по границам отрисовки и затем рисуется одним вызовом. Отдельный Matter.js больше не нужен.

Canvas ограничен DPR 2; за кадр выполняется максимум три шага. Скрытая вкладка приостанавливает симуляцию. Частицы ограничены, количество тел ограничено 70. Достижение лимита тел также запускает отсчёт переполнения, чтобы игра не зависала с заблокированным броском. React обновляет интерфейс по игровым событиям, без покадрового ререндера. У страницы нет прокрутки, выделения текста, перетаскивания картинок и контекстного меню. Поддерживаются безопасные области телефона, изменение ориентации и встраивание по относительному пути.

Превью верхнего фрукта следует прицелу через отдельную визуальную пружину и наклоняется по направлению движения. Физический бросок остаётся вертикальным и происходит в точной позиции прицела. Контроллер ленты `src/ui/ElasticScroll.ts` запускает кадры только во время движения и обновляет DOM без покадрового React-рендера. Анимации появления панелей, нажатий, счёта, очереди и открытия фруктов сделаны в CSS; окна сохраняют содержимое и паузу до конца анимации закрытия. Настройка `prefers-reduced-motion` уменьшает движение интерфейса и отключает инерцию превью. Фон — один чёткий слой с `background-size: cover` на всю ширину и высоту экрана. У масштабируемого игрового интерфейса нет отдельного фонового прямоугольника, поэтому на телефоне не видны края сцены.

## Ассеты

`public/assets/` содержит фруктовые спрайты, фоны со столешницей, стеклянные контейнеры и частицы. Все изображения включены в проект; внешний CDN не требуется. Из `public/assets/ui/generated/` интерфейс использует только 25 отдельных иконок; крестик закрытия выполнен чистым CSS. Кнопки, панели, окна, счёт и рамки фотографий сделаны на HTML/CSS без обводок. Скругления задаёт CSS-свойство `corner-shape: squircle` вместе с `border-radius`; старые WebView используют обычный `border-radius`. Старые текстуры сохранены как исходные ассеты, но больше не загружаются и не используются в UI. Игровые разделы занимают фиксированные строки сетки, длина чисел не меняет их размеры. Звуки синтезируются Web Audio; Nunito 700/800/900 с кириллицей поставляется локально через Fontsource. Желейность фруктов создаёт движок, максимум частиц — 150.

Полноэкранная стартовая загрузка показывает реальный прогресс изображений и шрифтов. Управление включается после загрузки всех ресурсов; при ошибке можно повторить загрузку. `scripts/prepare_assets.py` экспортирует фрукты и иконки, `scripts/prepare_polish.py` — вывеску и частицы, `scripts/prepare_shop_assets.py` — новые коллекции и измеренные квадратные границы тел из исходных сгенерированных изображений. `scripts/refresh_visual_assets.py` экспортирует отдельные новые фоны и исправленные спрайты, измеряя границы самого персонажа. Убраны фрагменты соседей в десяти спрайтах, огурец получил бугорчатую кожицу, усик и цветок. Начиная с драконьего фрукта спрайты перегенерированы, а их UV-контуры исправлены: квадратная лицевая часть масштабируется одинаково по обеим осям.

`src/game/fruits.ts` задаёт 11 ступеней 2 → 4 → … → 2048, размеры и цвета. `src/game/physics.ts` содержит правила и физический мир, `renderer.ts` — отрисовку, `audio.ts` — звуки. Исходный файл `Frame 44.webp` из репозитория сохранён.

## Магазин и награды

- Пять новых коллекций по 11 квадратных персонажей: шушистики, суши, овощи, фастфуд без брендов, кристаллы. Вместе с оригинальными фруктами — 66 персонажей.
- Четыре отдельных фона на основе первого: сакура на закате, лунный сад, сладкие холмы и снежные вершины. Каждый создан отдельно с широкой столешницей, исходные изображения перечислены в `scripts/visual-assets.json`. Три дополнительных контейнера. Магазин занимает весь экран: на одной вертикальной странице идут персонажи, затем фоны и боксы. Фон магазина — сама приостановленная игра, размытая через `backdrop-filter`, с лёгкой кремовой подложкой. Каждая конечная лента содержит один экземпляр товара и останавливается на первом и последнем; стрелки на границах отключаются. Квадратные CSS-карточки оформлены как фотографии Polaroid, между карточками — 28 px. Боковые фотографии постепенно уменьшаются по мере удаления от центра. При открытии каждая лента центрируется на надетом оформлении. Каждый раздел имеет фиксированную высоту 466 px и отдельные строки для заголовка, ленты, описания, пагинации и двух действий. Покупка или смена товара не сдвигает другие разделы. Цена и прогресс видео находятся под выбранной карточкой. Ленты используют native inertia и CSS scroll snap; вертикальный жест над ними прокручивает страницу. На компьютере доступны перетаскивание, горизонтальное колесо или Shift + колесо, стрелки клавиатуры, Home / End и кнопки навигации. Кнопка «Играть» всегда доступна внизу, баланс — вверху. Под шапкой закреплены переходы к персонажам, фонам, боксам, наборам и монетам; рядом находится компактная фиолетовая кнопка «+75» за видео.
- Любое оформление можно купить за монеты или открыть после 2–4 добровольных видео. Прогресс открытия сохраняется, выбор доступен только для принадлежащего игроку оформления. При применении загружается выбранный набор, затем атомарно меняются текстуры и UV; весь каталог не загружается на старте.
- Отдельный раздел ежедневных наград содержит цикл из 7 подарков: 25 монет, 2 встряски, 60 монет, эксклюзивное лунное стекло, 120 монет, фон с северным сиянием и 11 лунных моти. Один подарок за местный календарный день устройства; пропуск дня не сбрасывает прогресс. В следующих циклах уже открытое оформление заменяется монетами. Новые ассеты экспортирует `scripts/export_daily_assets.py`.
- Магазин предлагает два набора с оформлением и встрясками. Цена уменьшается, если часть оформления уже открыта; набор покупается один раз. В разделе монет и встрясок доступны 150 монет за два завершённых видео, встряска за видео, а также 1 встряска за 25 монет или 5 за 100. Дополнительные встряски сохраняются в профиле между играми; сначала тратятся три бесплатные за текущую партию, затем сохранённый запас, затем монеты.
- После проигрыша можно один раз убрать верхние кубики и продолжить за видео. Полученные за текущую игру монеты можно удвоить один раз; бонус фиксируется отдельно, поэтому продолжение после победы не удваивает будущие начисления.

Реклама сейчас **имитируется**: окно явно подписано, просмотр длится 3 секунды, его всегда можно закрыть. Отмена не даёт награду; завершение выдаёт её однократно. Скрытая вкладка останавливает отсчёт. Покупки, кошелёк, дневной подарок и прогресс видео сохраняются в localStorage; для реальной площадки потребуются SDK, проверенное событие завершения rewarded video и серверное/платформенное сохранение. `RewardedAd.tsx` — точка замены имитации на SDK; `completeAd` проверяет уникальный запрос перед начислением.

`npm test` проверяет семь ежедневных призов, защиту от повторного получения, эксклюзивное оформление, цены и однократную покупку наборов, сохранение запасов, переполнение движущейся стопки, восстановление крупных тел, однократное спасение/удвоение, покупки и сохранение прогресса. `npm run test:browser` также проверяет магазин и применение всех трёх типов оформления, отмену/полный просмотр видео, открытие скина после трёх видео, дневные подарки, надевание эксклюзивного бокса, закреплённую навигацию, наборы и пополнение запасов, а также реальные броски до проигрыша.

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускается при push в `main`: `npm ci` → тесты → сборка → загрузка артефакта → деплой Pages. Pull request выполняет проверки и сборку без публикации. Vite использует `base: './'`, поэтому игра работает и на `/2048Game/`.

Игра опубликована по адресу https://calloradc.github.io/2048Game/.

Прототип не содержит рекламного SDK, платежей или зависимости от конкретной игровой площадки. Сборку `dist/` можно использовать как статическую HTML5-игру.
