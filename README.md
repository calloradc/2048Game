# Jelly Fruit

Мобильный прототип гиперказуальной React-игры: квадратные фрукты с упругой деформацией падают в стеклянный контейнер. Два одинаковых кубика сливаются в следующий фрукт; цель — арбуз **2048**.

## Запуск

```sh
npm ci
npm run dev
```

```sh
npm test          # проверки физики и правил
npm run build    # TypeScript + production-сборка в dist/
npm run preview
```

Браузерные проверки выполняются отдельно при запущенном сервере:

```sh
npx playwright install chromium
npm run test:browser
# Для уже установленного Chromium:
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
# Для проверки production-сборки или вложенного пути Pages:
GAME_URL=http://localhost:4173/2048Game/ npm run test:browser
```

## Управление

- Игра начинается с пустого контейнера; числовых бейджей на фруктах нет.
- Веди пальцем и отпускай для броска. На компьютере — мышь и клик.
- Стрелки ← / → прицеливаются, пробел / Enter бросает, когда игровое поле в фокусе.
- Три встряски на игру помогают перемешать застрявшие кубики.
- Устоявшиеся фрукты выше пунктирной линии заканчивают игру после двух секунд; новый фрукт получает время на падение.
- Рекорд и настройка звука сохраняются локально. Есть пауза, справка, каталог фруктов и подтверждение перезапуска.

## Физика и производительность

Фрукт — физическое мягкое тело: восемь точек по контуру и одна в центре, 20 упругих связей и ограничение площади. Verlet-интеграция и XPBD-связи сохраняют объём, дают граням прогибаться при ударе и постепенно возвращают квадратную форму. Контакты рассчитываются по текущему деформированному контуру, давление распределяется на его ближайшие точки. Ограничитель формы предотвращает складывание и чрезмерное растяжение при переполнении.

Физика работает с фиксированным шагом 60 Гц и шестью итерациями решения. Пространственная сетка отбирает только соседние пары. Успокоившиеся тела засыпают. Спрайт следует тем же восьми точкам через восемь текстурированных треугольников; деформированный спящий фрукт кэшируется и затем рисуется одним вызовом. Отдельный Matter.js больше не нужен.

Canvas ограничен DPR 2; за кадр выполняется максимум три шага. Скрытая вкладка приостанавливает симуляцию. Частицы ограничены, количество тел ограничено 70. React обновляет интерфейс по игровым событиям, без покадрового ререндера. На экране нет прокрутки, выделения текста, перетаскивания картинок и контекстного меню. Поддерживаются безопасные области телефона, изменение ориентации и встраивание по относительному пути.

## Ассеты

`public/assets/` содержит 11 сгенерированных фруктовых спрайтов, иллюстрацию природы с деревянным столом, стеклянный контейнер и иконку. Все изображения уже включены в проект; внешний CDN не требуется. Фрукты остаются непрозрачными фруктовыми кубиками, желейность создаёт движок. Звуки синтезируются Web Audio после пользовательского взаимодействия. Montserrat 700/800/900 поставляется локально через Fontsource. В `public/assets/ui/` находятся девять сгенерированных поверхностей кнопок и плашек и пятнадцать иконок. В изображениях нет текста: все подписи отрисовываются отдельно. Контейнер использует только исходную картинку стекла, без дополнительных нарисованных слоёв.

`src/game/fruits.ts` задаёт 11 ступеней 2 → 4 → … → 2048, размеры и цвета. `src/game/physics.ts` содержит правила и физический мир, `renderer.ts` — отрисовку, `audio.ts` — звуки. Исходный файл `Frame 44.webp` из репозитория сохранён.

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускается при push в `main`: `npm ci` → тесты → сборка → загрузка артефакта → деплой Pages. Pull request выполняет проверки и сборку без публикации. Vite использует `base: './'`, поэтому игра работает и на `/2048Game/`.

Если Pages ещё не включён и токен workflow не может включить его автоматически, выбери в GitHub **Settings → Pages → Build and deployment → Source: GitHub Actions** и перезапусти workflow. Ожидаемый адрес: https://calloradc.github.io/2048Game/.

Прототип не содержит рекламного SDK, платежей или зависимости от конкретной игровой площадки. Сборку `dist/` можно использовать как статическую HTML5-игру.
